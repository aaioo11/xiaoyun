## 一、项目概述

一款面向闲鱼卖家的**轻量化 AI 客服 Chrome 扩展**。安装在浏览器后，自动在闲鱼商品页面注入悬浮入口，当买家发送咨询消息时，小云基于商品信息 \+ 自定义知识库，以人格化的语气自动回复。

### 核心差异化

> 🌟 **不做冰冷的 FAQ 机器。**
小云有温度、有性格——像一位靠谱的二手交易老手，自然地帮买家解答问题，让每次对话都让人觉得"这个卖家真好"。

### 产品决策记录

|决策点|选项 A|选项 B|最终选择|理由|
|---|---|---|---|---|
|**产品形态**<br>|Web SaaS（独立页面）<br>|Chrome 扩展|**Chrome 扩展** ✅|闲鱼是 SPA，扩展可直接注入 DOM，零跳转，体验最优；Web 方案需要 iframe 嵌套或跳转，体验断裂|
|**部署方式**|云端 SaaS|本地扩展|**本地扩展** ✅|闲鱼卖家不需要注册账号，即装即用；API Key 存在本地，数据安全|
|**LLM 架构**|单一模型硬编码|多 Provider 抽象|**多 Provider** ✅|适配不同预算和场景（免费 Ollama / 低价 DeepSeek / 高质量 Claude）|
|**RAG 方案**|向量数据库（Embedding）|关键词 BM25 检索|**BM25 关键词检索** ✅|MVP 阶段无需额外依赖；闲鱼场景知识条目少（通常 \<50 条），关键词匹配足够；向量方案增加延迟和成本|

> 💡 **为什么放弃 Web SaaS 转向 Chrome 扩展？**
最初设计是 Web SaaS——商家注册、录入产品、生成链接、发给客户。但在实际调研中发现：闲鱼卖家**不想注册新账号**，他们只需要一个"装上就能用"的工具。Chrome 扩展天然嵌入闲鱼页面，消息检测、自动回复、一键发送全部在闲鱼内完成，这才是真正的"无感 AI"。

## 五、背景与目标

### 现有问题

|问题|说明|
|---|---|
|🕐 **时间错位**|卖家不能 24 小时在线，买家夜间/工作时间发送的消息无人回复|

|💬 **体验差距**|手动回复慢、语气不一致；平台自带回复推荐太模板化|
|📦 **场景割裂**|现有 AI 客服都需要跳转到第三方页面，打断闲鱼原生购物体验|

### 产品目标

> 🎯 **让闲鱼卖家最低成本拥有一个 7×24 小时的 AI 客服**——安装扩展 → 配置 API → 自动开始服务。

### 成功指标

|指标|目标值|说明|测量方式|
|---|---|---|---|
|📈 **AI 自动回复率**|≥ 70%|买家消息中能由 AI 有效回复的比例|日志统计：AI 回复数 / 总买家消息数|
|⚡ **平均响应时间**|≤ 5 秒|从检测消息到自动发送的端到端时间|时间戳差值：消息到达 → 发送完成|
|🎯 **消息检测准确率**|≥ 95%|正确识别买家新消息，不误判、不漏判|人工抽检：误报数 / 总消息数|
|👥 **卖家使用留存（周）**|≥ 50%|开通后一周内仍保持使用的比例|chrome\.storage 中 enabled=true 的周活跃率|
|😊 **买家满意度（代理指标）**|≥ 4\.0 / 5\.0|买家未追问、未投诉即视为满意|同一买家连续消息间隔 \> 3 分钟且无追问|

### 7\.2 核心流程

#### 买家消息检测

```Plaintext
页面加载 → MutationObserver 监听 DOM 变化
                ↓
         是否在聊天页面？ → 否 → 跳过
                ↓是
       获取左侧消息气泡元素
                ↓
       过滤：非空 / 长度 1-200 / 未处理过
                ↓
       触发 AI 自动回复
```

#### AI 自动回复流程

```Plaintext
检测买家消息
    ↓
检查配置（enabled + autoReply + apiKey）
    ↓
调用 Background Service Worker → callLLM()
    ↓
Background 执行：
  1. 加载会话上下文（最近 8 轮）
  2. RAG 知识库检索（Top-3 匹配）
  3. 构建 System Prompt（人格 + 商品信息 + 知识库）
  4. 调用 LLM API 生成回复
    ↓
Content Script 接收回复文本
    ↓
查找输入框 → 填入文本 → 触发 input / compositionend 事件
    ↓
查找发送按钮 → 点击发送
    ↓
自动滚动到买家消息位置（高亮闪烁）
```

## 九、AI 策略

### 9\.1 技术架构

```Plaintext
买家消息 → RAG 知识库检索（Top-3）
                  ↓
    System Prompt（人格 + 商品信息 + 检索结果）
                  ↓
    附加最近 8 轮会话上下文
                  ↓
    调用 LLM API → 生成回复 → 自动发送
```

### 9\.2 Prompt 工程设计

#### System Prompt 组成

System Prompt 由四部分动态拼接：

|组成部分|来源|权重|说明|
|---|---|---|---|
|🎭 **人格指令**|硬编码|固定|小云的性格、说话风格、颜文字使用规则|
|📦 **商品信息**|chrome\.storage|固定|当前商品标题、价格|
|📚 **知识库上下文**|RAG 检索|动态|与买家消息最匹配的 Top\-3 知识条目|
|🌡️ **热情度**|用户配置|可调|安静型 / 正常型 / 热情型|

#### 模型参数设计

|参数|值|理由|
|---|---|---|
|**Temperature**|0\.8|平衡创造性和准确性；太低则回复僵硬，太高则偏离事实|
|**Top\-P**|0\.9|允许一定多样性，但排除极低概率的 token|
|**Max Tokens**|150|限制回复长度，确保两句话、≤80 字|

#### Prompt 迭代记录

|版本|修改内容|效果|结论|
|---|---|---|---|
|**V1**|"你是一个客服助手，回答用户问题"|回复像机器人，模板化严重|❌ 缺少人格约束|
|**V2**|加入人格描述 \+ 说话风格规则|语气自然了一些，但颜文字滥用|⚠️ 需要量化约束|
|**V3**|增加"每条最多 1 个颜文字""固定两句话"|回复质量显著提升|✅ 保留|
|**V4**|加入"跳过无意义消息"规则|减少了 30% 无效 API 调用|✅ 保留|

### 9\.3 回复规则

|规则|说明|
|---|---|
|📏 **固定两句话**|不多不少，第一句回应买家，第二句补充或关心|
|✂️ **≤ 80 字**|保持简短，像真人聊天|
|😀 **颜文字克制**|一条最多 1 个，情绪匹配，不连续使用|
|🚫 **跳过无意义**|纯标点 / 空格 / 空消息不触发回复|
|📖 **知识库优先**|有相关知识基于知识回答，没有则如实告知|

### 9\.4 知识库检索（RAG）

轻量级 BM25 风格检索，无需向量数据库：

```Plaintext
买家消息 → 提取中文双字关键词（去停用词）
                ↓
         逐条计算知识条目匹配分：
           · 关键词在 text 中出现：+10 分
           · 关键词在 keywords 中出现：+8 分
           · 消息包含条目标题：+20 分
           · 字符重叠率：× 5 倍加权
           · FAQ 类型：+3 分加成
                ↓
         取 Top-3 → 拼入 System Prompt
```

#### 为什么选择 BM25 而非 Embedding？

|维度|BM25 关键词检索|Embedding 向量检索|
|---|---|---|
|**实现复杂度**|零依赖，纯 JS 实现|需引入向量库或 Embedding API|
|**延迟**|\< 10ms|50\-200ms（API 调用）|
|**成本**|免费|每次检索增加 $0\.001|
|**适用场景**|知识条目 \< 100 条|知识条目 \> 1000 条|
|**准确性**|闲鱼场景足够|略优，但边际收益有限|

> **决策依据：** MVP 阶段知识条目通常在 10\-30 条，BM25 完全够用。后续若扩展到 100\+ 条，可引入 Embedding 方案。

### 9\.5 幻觉控制

|风险|应对策略|
|---|---|
|AI 编造产品信息|System Prompt 中明确"如果知识库中没有相关信息，请如实告诉用户，不要编造"|
|关键信息（价格/库存）出错|商品信息从 chrome\.storage 读取，不依赖 AI 记忆|
|回复过于发散|Max Tokens=150 \+ Temperature=0\.8 双重约束|
|知识库检索不相关|检索分数低于阈值时不拼入 Prompt（静默忽略）|

### 9\.6 坏案闭环

1. AI 回复失败时，控制台记录错误信息

2. 找不到输入框时，弹出回复提示浮窗（可复制 / 手动发送）

3. API 调用超时（30s）自动降级，返回错误提示

4. 商家可通过 Popup 查看知识库覆盖情况，定期补充

## 十一、风险与应对

|风险|影响|应对方案|
|---|---|---|
|🤖 **AI 幻觉（编造产品信息）**|误导买家，引起售后纠纷|知识库严格限制；"拿不准就如实告知"；关键信息（价格/库存）加强制校验指令|

|😐 **用户觉得 AI 回复"假"**|失去信任，关闭扩展|小云核心原则是"自然不装"；颜文字克制使用；可调节热情度|

|⏰ **API 调用失败/超时**|消息未回复|30 秒超时降级；弹窗提示"已填入，请手动发送"；控制台记录错误|
|🔁 **重复回复消息**|体验差|Set 缓存已处理消息文本（最多 100 条），进入聊天页面时自动清空|
